# Codex Retain 0.1.1

Fixes 0.1.0 skipping paginated archives while reporting verified compatibility.

- Supports archived paginated JSONL and zstd rollouts, including multiple
  segments belonging to one thread after revert.
- Preserves a thread while another thread still references any of its segments.
  Removing an expired leaf never removes the source it depends on.
- Keeps pins, exclusions, spawn-related protection and existing retention clocks.
- Adds history-format counts to doctor/status, separately from schema/binary
  validation and actual deletion eligibility.
- Adds journal schema 3 for restartable multi-segment deletion, including owner
  validation during recovery. The journal remains bounded to 128 files.

## Update

```sh
brew update
brew upgrade dankosik/codex-retain/codex-retain
codex-retain --version
codex-retain status
```

Installer users can rerun the installer from the latest release. Existing
policies and their grace periods are preserved; no re-enabling is needed when
updating at the same installation path.

Compatibility remains Codex 0.153.4 on macOS 15+ for ARM64 and Intel. Native
synthetic conformance was exercised with both the npm CLI and the tested Desktop
embedded 0.153.4 executable. This does not certify arbitrary Desktop builds.
Separate paginated projection caches and other secondary stores are retained.
Complete any pending recovery with 0.1.1 before downgrading: 0.1.0 cannot read
schema-3 journals.

[Source contract and verification](https://github.com/Dankosik/codex-retain/blob/0.1.1/docs/paginated-support.md).
