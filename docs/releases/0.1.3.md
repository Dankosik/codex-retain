# Codex Retain 0.1.3

Reduces repeated rollout-header reads during large archive cleanups while
preserving fresh filesystem discovery and dependency checks before each group.

- Reuses parsed headers within one run only when a fresh file stat matches
  identity, size, modification/change times, permissions and link count. New or
  changed files are read again; missing files leave the next dependency graph.
  Orphan files and every physical copy remain part of discovery.
- Continues to validate candidate and staged files independently under the
  existing locks and SQLite transaction. A new dependency still blocks deletion,
  including when SQLite itself has not changed.
- Syncs each distinct source/staging directory once before the SQL commit,
  retaining the separate barrier after staged-file removal.
- Refreshes the README with current format coverage, installation examples,
  recovery behavior and performance evidence. Includes all previously local
  verification reports and raw benchmark receipts.

In a fresh synthetic comparison with installed 0.1.2, deleting 10,000 legacy
archives fell from **12.80 to 7.59 seconds by median (41% less time)**. The
pre-release optimization candidate used about 5.5 MiB more sampled process RSS
on that workload. Small paginated results remain noisy and do not establish a
speedup; a small regression cannot be ruled out. The initial large preview still
reads the full header inventory. These are measurements of the recorded local
candidate, not of the subsequently built release archives.

[Complete measurements, samples and limits](https://github.com/Dankosik/codex-retain/blob/0.1.3/docs/inventory-performance-2026-09-10.md).

## Update

```sh
brew update
brew upgrade dankosik/codex-retain/codex-retain
codex-retain --version
codex-retain status
```

Installer users can rerun the installer at the same installation directory.
Installation does not enable retention. Existing policy, exclusions, archive
grace periods and journal schemas remain unchanged. Finish pending recovery
with 0.1.2 or newer before downgrading to an older reader.

Compatibility remains the reviewed Codex 0.153.4 storage protocol, with macOS
15+ archives for Apple Silicon and Intel. Native conformance evidence uses
isolated synthetic profiles; organizational relationships are constructed after
native startup and are not a model-driven spawn certification. Separate
projection caches and other secondary stores remain outside cleanup.
