# Codex Retain 0.1.4

Retention starts helping during setup: `enable --days 30 --yes` now performs
the first cleanup immediately, using Codex's existing archive dates.

- Existing chats recorded as archived more than the selected number of days
  ago can be removed during enable. Recent archives keep their remaining time.
  Missing, invalid and future archive dates remain protected.
- Pins, exclusions, dependent chats, shared history, writer locks and artifact
  checks apply to the initial cleanup exactly as they do to later runs.
- Hourly scheduling continues after the initial cleanup. `--no-schedule` also
  cleans once during enable, with subsequent passes run manually.
- Initial results are saved in the normal last-run receipt. Artifact problems
  return exit 3 with the policy still enabled for later retries.
- The `enable` JSON response advances to schema 2. `existing_archives_assessed`,
  `initial_archive_clock` and `initial_cleanup` replace the fresh-grace fields.
  Policy, capture, recovery-journal and other command schemas are unchanged.

At activation, Retain trusts the existing `archived_at` recorded by Codex. Codex
can reconstruct that timestamp during metadata repair, so it does not prove
continuous archive time before Retain was installed. Retain never substitutes
chat creation time, last-message time or file mtime for a missing archive date.
After activation, archive/restore/rearchive and timestamp-repair transitions
continue to be captured transactionally.

## Update and adopt the new initial cleanup

```sh
brew update
brew upgrade dankosik/codex-retain/codex-retain
codex-retain --version
```

An ordinary package update preserves an already enabled policy and its captured
periods. To explicitly adopt historical archive dates, disable and re-enable
using the same profile, Codex executable, retention days and scheduling options:

```sh
codex-retain disable
codex-retain enable --days 30 --yes
codex-retain status
```

Use your original `--state-dir`, `--codex-home`, `--codex-bin` and `--no-schedule`
options when customized. Exclusions are preserved. Re-enabling can permanently
delete old eligible archives immediately. Installing a binary by itself still
does not enable retention or delete chats.

Compatibility remains the reviewed Codex 0.153.4 protocol, with macOS 15+
packages for Apple Silicon and Intel. Validation uses synthetic profiles.

[Behavior and verification](https://github.com/Dankosik/codex-retain/blob/0.1.4/docs/initial-archive-cleanup.md).
