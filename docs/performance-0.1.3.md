# Производительность окончательной реализации 0.1.3 — 10 сентября 2026

После исправления свежести кеша время удаления 10 000 legacy-файлов сократилось
с **16,33 до 9,16 с по медиане (−43,9%; ускорение 1,78×)** в свежей сопоставимой
серии. Малый paginated-сценарий остаётся шумным, заметный выигрыш не установлен.

## Исправленный кандидат

Исходный кандидат из [предыдущего отчёта](inventory-performance-2026-09-10.md)
не был выпущен в таком виде. [Linux CI](https://github.com/Dankosik/codex-retain/actions/runs/34509292383)
обнаружил, что две быстрые записи одинаковой длины могут иметь одинаковые
mtime/ctime. [Документация ядра Linux](https://docs.kernel.org/filesystems/multigrain-ts.html)
объясняет, почему наносекундные поля не гарантируют различимость изменений
в пределах одного грубого такта часов.

Теперь cache admission и reuse требуют, чтобы **оба** времени файла предшествовали
предыдущей полной секунде относительно начала скана. Недавно изменённые,
будущие и неоднозначные по часам заголовки перечитываются; в последующем скане
они могут попасть в кеш после закрытия этого временного окна. Это влияет
только на переиспользование чтений, не на срок хранения или право удаления.
Проверка inode/размера/прав/link count, повторное построение графа и все
проверки кандидатов и staging сохранены. Неверный или неполный скан очищает кеш.

Добавлен детерминированный тест запрета reuse свежих заголовков. Проверки
изменения уже кешированных файлов отдельно дожидаются закрытия реального
временного окна, чтобы упражнять cache hit/invalidation. Исправленная версия
прошла 192 Rust-теста, 26 тестов релизных инструментов, 7 тестов навыков и
[полный Linux/macOS CI](https://github.com/Dankosik/codex-retain/actions/runs/34512373286).

## Новая серия

Сравнивается установленная 0.1.2 с локальной release-сборкой окончательной
реализации 0.1.3 из тега `0.1.3`, коммит
`1e99b901c1c1aae575e98fab50936df8286f909f`. Rust 1.98.1, ARM64, macOS 26.4,
MACOSX_DEPLOYMENT_TARGET=15.0, обычный release profile. SHA-256 бинарника:
`a82d737e4ce10471d5d079bc72f75bc2269f3a44a55b855cd672cc657373181d`.
Это локально собранный executable; опубликованные GitHub archives собраны и
проверены отдельно на нативных macOS 15 runners.

Три прогрева и пять timed runs на каждую комбинацию, всего 30 измерений.
Пары используют один путь, политику и исходный набор независимых 4-КиБ архивов.
Перед каждым удалением fixture восстанавливается вне таймера. Заголовкам
**не добавлялась искусственная выдержка времени**: новые файлы проходят
обычное консервативное правило кеша. Каждый destructive sample проверяется
после исполнения. Сборки и другие тесты на этом хосте во время замеров не шли;
фоновые приложения и файловый кеш не изолированы. Порядок сборок чередуется
между legacy-сценариями. Дополнительных серий после получения этих результатов
не проводилось.

| Нагрузка | 0.1.2, медиана | 0.1.3, медиана | Изменение |
| --- | ---: | ---: | ---: |
| Удаление 1 000 legacy | 0.799 с | 0.557 с | -30.3% |
| Удаление 10 000 legacy | 16.331 с | 9.158 с | -43.9% |
| Удаление 1 000 независимых paginated | 0.660 с | 0.628 с | -4.9% |

Для 10 000 legacy диапазоны не пересекаются: **7,960–12,162 с** у кандидата
против **15,697–18,445 с** у 0.1.2. Средние — 9,653 ± 1,752 с и 16,621 ± 1,067 с.
Ни один из пяти запусков кандидата не достиг времени самого быстрого baseline.
Для 1 000 legacy диапазоны также разнесены: 0,529–0,666 против 0,698–0,848 с.
Эти коэффициенты относятся к этой серии, не ко всем профилям или машинам.

Для 1 000 paginated диапазоны перекрываются: 0,551–0,882 против 0,516–0,783 с.
Среднее кандидата даже немного выше: 0,665 против 0,651 с. Медиана −4,9%
не подтверждает устойчивого ускорения. Сохраняется прежний вывод: обычные
небольшие paginated-архивы не являются доказанным источником крупного выигрыша.

В отдельном RSS-наблюдении удаления 10 000 файлов максимум процесса составил
31,59 против 26,78 МиБ, разница около 4,81 МиБ. Это sampled parent RSS, способный
пропустить пик и не включающий дочерние процессы. Кеш хранит поля заголовков
и файловые отпечатки; полные строки и открытые дескрипторы в нём не остаются.

Большой первоначальный preview и scheduled no-candidate path повторно не
измерялись: исправление касается только run-cache. Preview всё ещё выполняет
полный необходимый первый обход; scheduled без кандидатов по-прежнему его
пропускает. Не заявляется новое ускорение этих путей, cold-cache, других
платформ или задержек живых Codex writers.

```sh
/opt/homebrew/bin/rtk proxy python3 scripts/performance_matrix.py run \
  --baseline /opt/homebrew/Cellar/codex-retain/0.1.2/bin/codex-retain \
  --candidate "$PWD/target/aarch64-apple-darwin/release/codex-retain" \
  --codex-bin /Applications/ChatGPT.app/Contents/Resources/codex \
  --root /private/tmp/new-retain-0.1.3-legacy \
  --cases cleanup --runs 5 --rss

/opt/homebrew/bin/rtk proxy python3 docs/evidence/inventory-optimization-2026-09-10/paginated_matrix.py run \

```
