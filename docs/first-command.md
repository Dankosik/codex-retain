# Development and isolated validation

Read `AGENTS.md` and the design before changing deletion policy. Rust 1.98.1 and
edition 2024 are pinned. The public interface lives in `src/cli.rs`; policy and
process decisions in `src/lib.rs`; SQLite compatibility in `src/database.rs`;
eligibility and crash recovery in `src/engine.rs`; file/lock mechanics in
`src/fsutil.rs`; launchd behavior in `src/scheduler.rs`.

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
make maintenance-check
```

Tests build a fresh exact-schema SQLite database and synthetic transcripts.
`tests/lifecycle.rs` exercises clocks, preservation, file identity, zstd,
interrupted deletion, SQLite rollback and independent OS-lock contenders.
`tests/cli.rs` runs the executable; its fake version command tests CLI dispatch,
not Codex compatibility. The source/real-binary evidence is documented separately
in `docs/compatibility-research.md`. Scheduler tests use mock command runners and
temporary directories; they do not register a real LaunchAgent.

To inspect a reproducible synthetic profile without user data:

```sh
python3 scripts/fixture.py create --root /absolute/new/scratch --count 1000
target/release/codex-retain doctor --codex-home /absolute/new/scratch/codex --codex-bin /path/to/codex
```

Benchmark fixtures have explicit ownership markers and never reuse the user's
default home. Destructive comparisons require a marked fixture generated by the
provided helper. Benchmark-only SQL backdates capture epochs in those synthetic
profiles; the production CLI has no fake-clock or force-delete option.

To add a Codex version, inspect actual archive, unarchive, pin, write,
compression, migration and reference paths; capture a pristine schema/migration
manifest; run real-binary lock and transition tests; then extend the reviewed
adapter. A permissive version range or column-existence check is not equivalent
evidence. Do not replace supplied fixtures with real chat contents.
