# Оптимизация инвентаризации — 10 сентября 2026

Локальный кандидат сократил время очистки 10 000 legacy-файлов на 40,7%
по медиане в свежем сравнении с 0.1.2. Он повторно использует проверенные заголовки между
группами удаления; каталоги и зависимости проверяются заново перед каждой группой.
Установленная 0.1.2, реальные профили и расписание не изменялись.

## Изменение

Кеш действует только внутри одного `run` и хранит разобранные поля заголовка
и файловый отпечаток по физическому пути. Для повторного использования свежий
`symlink_metadata` должен совпасть по device/inode, размеру, mtime/ctime с
наносекундами, режиму, uid/gid и числу ссылок. Новые и изменившиеся файлы
открываются и разбираются заново. До помещения в кеш проверяется неизменность
метаданных того же открытого inode за время чтения. Ошибка обнуляет кеш.

Обход обоих деревьев, обнаружение orphan-файлов и физических копий, лимит
инвентаря и построение графа остаются перед каждой группой под прежними
блокировками и `BEGIN IMMEDIATE`. Исчезнувшие файлы исключаются из нового графа
и кеша. Проверки кандидатов и staged-файлов самостоятельно открывают заголовки;
кеш не хранит разрешения на удаление. SQLite data_version не используется
как свидетельство неизменности файлов.

Source и staging directories объединены перед fsync. Для плоского архива
остаются две разные границы durability: перед SQL commit и после unlink.
Каждая синхронизирует archive directory один раз.

Для 10 000 неизменяющихся независимых файлов и групп по 128 расчётное число
чтений заголовков **в инвентаризации** сокращается с 405 632 до 10 000.
Повторные обходы и stat остаются; отдельные чтения кандидатов и стадийных
файлов в этот расчёт не входят. Это расчёт по алгоритму, не трасса syscall.

`preview` не создаёт кеш. Первый полный проход по заголовкам по-прежнему
нужен, в том числе когда среди 100 000 файлов просрочен только один архив.
Ускорение этого пути данной оптимизацией не заявляется.

## Проверки

`make check` прошёл: форматирование, Clippy с `-D warnings`, все Rust-тесты
и doctests. Пять добавленных тестов проверяют повторное использование,
новые/исчезнувшие копии и ссылки, изменение одинаковой длины, восстановленный
mtime, замену inode, append, zstd, опасные ссылки, изменение прав, неверный
заголовок и pending artifact. Между двумя реальными группами удаления новая,
переписанная или заменённая orphan-родительская ссылка блокирует удаление
даже при неизменном SQLite data_version. Отдельно проверено число fsync
архивной папки.

Сборка: Rust 1.98.1, ARM64 macOS, обычный locked release profile. Локальный
rust-objcopy первоначально не нашёл LLVM dylib; тот же шаг `--strip-debug`
завершён с явным DYLD_LIBRARY_PATH на библиотеку этого toolchain.
`codesign --verify` и запуск готового executable прошли.

## Условия сравнения

Сравниваются установленная 0.1.2 и новый локальный release executable.
Нативные команды измеряются Hyperfine с тремя прогревами и пятью запусками,
с общими для каждой пары путями, политикой и исходными файлами. Перед каждым
удалением синтетическая фикстура восстанавливается вне таймера; после него
проверяются данные. Порядок сборок чередуется между сценариями. Все образцы,
включая выбросы, сохраняются. Фоновые приложения хоста не изолированы;
сборки и другие проверки во время замеров не выполнялись.

RSS наблюдается отдельно от Hyperfine, только у родительского процесса.
Это выборочная нижняя оценка пика, а не точный allocation profile.

## Результаты

В свежем сравнении очистка 10 000 legacy-файлов сократилась с **12,80 до
7,59 с по медиане (−40,7%; ускорение 1,69×)**. Все пять запусков кандидата
быстрее всех пяти запусков исходной версии: 7,260–7,858 против 12,351–14,504 с.
Средние — 7,558 против 13,247 с. Это основное подтверждённое улучшение.

| Нагрузка | 0.1.2, медиана | Кандидат, медиана | Изменение |
| --- | ---: | ---: | ---: |
| Удаление 1 000 legacy | 0.557 с | 0.537 с | -3.6% |
| Удаление 10 000 legacy | 12.799 с | 7.589 с | -40.7% |
| Scheduled: 100 000 непросроченных архивов | 0.375 с | 0.358 с | -4.4% |
| Preview: 99 000 активных + 1 000 непросроченных | 0.179 с | 0.148 с | -17.8% |
| Preview: тот же профиль, один архив просрочен | 13.561 с | 14.138 с | +4.3% |
| Удаление 1 000 независимых paginated | 1.369 с | 1.492 с | +9.0% |

Для 1 000 legacy диапазоны перекрываются: 0,493–0,700 против 0,530–0,882 с.
Значительный выигрыш на этой нагрузке не установлен. Средние scheduled-прохода
практически одинаковы: 0,380 с у обеих сборок. Изменение короткого mixed-none
пути не приписывается кешу: этот сценарий вообще не читает lineage-заголовки.

Большой preview остаётся дорогим: диапазоны 13,085–22,582 против
12,056–17,386 с; средние 16,288 против 13,985 с. Все выбросы сохранены.
Медиана кандидата выше на 4,3%; ускорение первоначального чтения не получено.

На 1 000 paginated первоначальная серия дала +9,0% к медиане и +13,6% к
среднему. Диапазоны — 1,285–1,662 против 0,979–1,815 с. Из-за неоднозначности
этого результата проведена **одна заранее ограниченная дополнительная серия**:
пять пар с чередованием порядка сборок, один измеряемый native run после трёх
прогревов в каждом блоке. Подготовка и проверка снова вынесены из таймера.

В дополнительной серии медианы — 0,884 против 0,911 с (−2,9%), но средние —
0,932 против 0,832 с (+12,1%). Кандидат быстрее только в двух из пяти пар;
парные изменения от −15,5% до +47,0%. Устойчивое ускорение малых paginated
архивов **не подтверждено**, небольшой регресс исключить нельзя. Обе серии
сохранены отдельно; дополнительные прогоны ради более выгодного числа не делались.
[Пары и агрегаты](evidence/inventory-optimization-2026-09-10/paginated-interleaved/comparison.json),
[фиксированный план](evidence/inventory-optimization-2026-09-10/paginated-interleaved/plan.json).

В отдельном наблюдении удаления 10 000 файлов максимум sampled parent RSS
составил 31,6 против 26,1 МиБ: разница около 5,5 МиБ. Кеш добавляет O(числа
файлов) состояния в памяти; удалённые записи убираются после следующего обхода.
Полные строки заголовков и файловые дескрипторы в кеше не удерживаются.

Прежние 34,53 с для 0.1.2 из [первого отчёта](performance-0.1.2.md) не используются
как база нового коэффициента: свежая исходная серия здесь существенно быстрее.
Это подчёркивает ограничение работающего desktop-хоста и необходимость сравнивать
обе сборки в одной серии.

## Итоговая проверка

60 timed runs основной матрицы и 10 timed runs дополнительной серии завершились
с ожидаемыми исходами. Каждый destructive sample прошёл conclude-проверку.
Полные preflight/postflight-проверки подтверждают counts, набор оставшихся
файлов и их содержимое, строки SQLite, capture epochs, защищённые метаданные,
целостность/внешние ключи и отсутствие pending recovery.
[Проверка сохранённых receipts](evidence/inventory-optimization-2026-09-10/validation.json)
содержит их SHA-256.

На embedded Codex **0.153.4** прошли
[13 paginated/fork/revert проверок](evidence/inventory-optimization-2026-09-10/native-paginated.json)
и [15 проверок организационных связей](evidence/inventory-optimization-2026-09-10/native-related.json).
Все профили синтетические, HOME/CODEX_HOME изолированы; model turns и установка
LaunchAgent — ноль. Организационные связи сконструированы после native startup,
поэтому это не подтверждение настоящего model-driven spawn. Отдельные projection
caches и другие локальные хранилища не входят в заявленное удаление.

Публикация, установка кандидата и другие платформы не проверялись и не выполнялись.

## Воспроизведение

Сначала собрать candidate executable. Для каждой команды нужен новый,
несуществующий scratch root; использовать только маркированные синтетические
профили, создаваемые harness.

```sh
/opt/homebrew/bin/rtk proxy python3 scripts/performance_matrix.py run \
  --baseline /opt/homebrew/Cellar/codex-retain/0.1.2/bin/codex-retain \
  --candidate "$PWD/target/release/codex-retain" \
  --codex-bin /Applications/ChatGPT.app/Contents/Resources/codex \
  --root /private/tmp/new-retain-inventory-legacy \
  --cases cleanup summary mixed --runs 5 --rss

/opt/homebrew/bin/rtk proxy python3 docs/evidence/inventory-optimization-2026-09-10/paginated_matrix.py run \
  --baseline /opt/homebrew/Cellar/codex-retain/0.1.2/bin/codex-retain \
  --candidate "$PWD/target/release/codex-retain" \
  --codex-bin /Applications/ChatGPT.app/Contents/Resources/codex \
  --root /private/tmp/new-retain-inventory-paginated \
  --cases cleanup --runs 5 --rss

/opt/homebrew/bin/rtk proxy python3 docs/evidence/inventory-optimization-2026-09-10/paginated_interleaved.py \
  --root /private/tmp/new-retain-inventory-paginated \
  --output /private/tmp/new-retain-inventory-paginated-interleaved
```

Крупные временные синтетические фикстуры удалены после сохранения результатов;
[cleanup receipt](evidence/inventory-optimization-2026-09-10/scratch-cleanup.json)
перечисляет только созданные этой задачей маркированные профили.
